# Advisory: F-150 by architecture-advisor round 1

Scope reviewed: `migration/specs/F-150.md`, root/desktop manifests and lockfiles, `.github/workflows/desktop-build.yml` and `release.yml`, `desktop/src/main.rs`, and F-002 package/tests/source at `migrate/F-002-review-fixes` (`62db2ce`). Reconciles `migration/reports/F-150/platform-review-1.md`. Verdict: **PROCEED WITH CHANGES**. Builds, locked package checks, and native PTY/ConPTY replay are implementable. Two material clarifications are needed: explicitly target the one real cross-platform live scenario, and treat native-window smoke as an experiment until both hosted OSes prove window discovery and shutdown.

## Recommendations (ranked)

1. **R1 [must] Specify separate locked-package commands.** The root TUI, `desktop/`, and `tools/ira-parity/` are three independent Cargo packages with distinct lockfiles; there is no root workspace. For each manifest, run `cargo build --manifest-path <manifest> --locked`, `cargo test --manifest-path <manifest> --all-targets --locked`, `cargo clippy --manifest-path <manifest> --all-targets --locked -- -D warnings`, and `cargo fmt --manifest-path <manifest> -- --check` (format checks can be scoped to that package). Root and desktop test/build commands should run on all three OSs. Evidence: `Cargo.toml`, `desktop/Cargo.toml`, `tools/ira-parity/Cargo.toml`; existing artifact-only workflow has just a release build. **Risk:** a workspace shorthand could omit one package or use the wrong lockfile.

2. **R2 [must] Name an exact live replay test; do not use blanket `--ignored`.** The package has no replay CLI. `f002_contract::tagged_oracle_trace_replays_on_linux_macos_windows` is currently an unignored, cross-platform integration test that reads `migration/oracle/traces/harness/resize_small.toml`, whose platform list covers Linux, macOS, and Windows MSVC, then calls `run_oracle_trace` (native backend via `portable_pty::native_pty_system()`). Run it separately, e.g. `cargo test --manifest-path tools/ira-parity/Cargo.toml --locked --test f002_contract tagged_oracle_trace_replays_on_linux_macos_windows -- --exact --test-threads=1`, on each native runner and assert/report one test passed, scenario ID, baseline SHA, and successful cleanup. This selects only the live test without running unrelated ignored GAP probes. Also run the normal crate suite, but treat remaining GAP-annotated ignores as unresolved F-002 coverage; Cargo's successful exit alone does not prove “no skips.” The macOS PTY and Windows ConPTY adapter tests in `f002_contract.rs` are currently both `#[ignore]`, but the named live replay itself uses the selected host's native backend and is stronger evidence than those adapter-only probes. Evidence: `tools/ira-parity/tests/f002_contract.rs` near the native adapter tests and `tagged_oracle_trace_replays...`; `tools/ira-parity/src/runner.rs` PTY implementation; `resize_small.toml`. **Risk:** plain `cargo test` silently skips the explicit ignored cases; blanket `--ignored` runs unrelated GAPs and does not identify the desired contract.

3. **R3 [must] Preserve baseline-tag fetch and identity proof in CI.** The resolver in `tools/ira-parity/src/baseline.rs` verifies peeled `tui-oracle-baseline` against `1cad4ce43cc72d52d4cc4eef920e0da22cb69568` and explicitly fetches the tag if missing. A shallow checkout can still work because that fetch is implemented; nevertheless, make checkout fetch behavior explicit (full history or explicitly fetch the tag) and log the verified SHA so CI evidence is auditable. Keep the oracle build from the detached tag and locked baseline root manifest, not the current checkout binary. **Risk:** tag removal/retargeting or fetch failure becomes opaque, and build provenance cannot be confirmed from a green test line.

4. **R4 [must] Make the license check deterministic over the parity lock closure, including target-specific edges.** Audit `tools/ira-parity/Cargo.toml` and its own `Cargo.lock`, not either application lockfile. Pin the cargo-deny version; commit `deny.toml`/policy plus a generated inventory containing package/version/SPDX expression/source; reject unknown or disallowed expressions. Configure dev dependencies explicitly (current F-002 manifest has no `[dev-dependencies]`, but test targets still use normal package dependencies). Check all three target profiles, or demonstrate that the pinned cargo-deny invocation validates the complete lockfile graph independent of host target; the lock includes Windows-only packages. Verify command syntax against the pinned cargo-deny CLI when implementing rather than copying an unpinned action example. **Risk:** host-only `cargo tree`/metadata or root-lock scanning can omit ConPTY dependencies. Evidence: parity manifest/lock and platform review inventory of 61 lock entries.

5. **R5 [must] Resolve the GUI smoke clause as an explicit CI experiment and gate.** `desktop/src/main.rs` creates and activates a GPUI window and registers `app.on_reopen(open_main_window)`, but `.github/workflows/desktop-build.yml` only builds, bundles, and signs; it proves no runtime behavior. Prototype on the chosen macOS and Windows hosted labels: launch the desktop executable, use OS-native window enumeration to assert its window is visible, request window close, and assert process shutdown within a deadline. A process-start/exit check or compilation is not a window smoke. Record runner image and outcome. If hosted jobs cannot reliably provide the required display/window assertion, record the unresolved limitation and implement a separately agreed automated GUI runner/strategy before claiming clause 6; the current conditional text is not evidence that hosted GUI works. **Risk:** falsely treating a headless launch or successful link as successful native window creation. This agrees with platform review R4.

6. **R6 [should] Pin/report runner and Rust toolchain inputs and preserve workflow separation.** Use explicit supported labels (platform review recommends `ubuntu-24.04`, `macos-15`, `windows-2022`; choose Intel macOS only if x86_64 is in scope), print `rustc -Vv`, `cargo -V`, and runner image identifiers, pin the Rust toolchain and cargo-deny/action versions, and key caches with OS, target, toolchain, and relevant lock hashes. Trigger PRs, integration-branch pushes, and manual dispatch. Keep `desktop-build.yml` packaging behavior separate; new migration workflow should have read-only repository permissions and no release-publishing step. Evidence: current desktop workflow uses floating `stable`, `macos-14`, `windows-latest`; release publishing lives separately in `release.yml`. **Risk:** green evidence can drift with runner/tool versions or accidentally conflate CI checks with artifact publication.

## Risks / missing gates

- On the integration branch at `87d6e5b`, `tools/ira-parity/Cargo.toml` and its lockfile were absent; the F-002 package is on a separate branch. F-150 cannot honestly be implemented/run until F-002 is integrated. Re-check the integration branch at implementation time.
- The repository already records pre-existing strict root fmt/clippy findings (see `migration/STATE.md` and `migration/DECISIONS.md`). F-150 should expose these as failures, then resolve behavior-preservingly or use a reviewed, narrow baseline policy; it must not silently weaken `-D warnings` or hide the failing command.
- F-150 CI is evidence for only its exact commit. The spec should say all ignored GAP probes must be resolved/explicitly tracked before the overall parity gate can pass, even if the dedicated live test succeeds.
- No hosted macOS/Windows GUI smoke was executed in this review. The native window requirement remains unverified until prototype results exist.
