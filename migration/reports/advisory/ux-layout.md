# Advisory: UX layout by ux-advisor round 1

Scope reviewed: `migration/inventory/rendering-messages.md`, `state-search.md`, `files-ops.md`, `preview-external.md`, `config-state.md`; `src/ui/mod.rs`, `src/components/tab1_files_ui.rs`, `src/components/{drives_ui,common_folders_ui,bookmarks_ui,actions_ui,preview_ui,copy_board_ui}.rs`; `desktop/src/main.rs`; pinned GPUI notes.

Summary verdict: PROCEED WITH CHANGES. Use a dense, resizable single-window browser organized around the TUI's two-pane state, with a TUI-like default profile that does not silently force the optional split or Copy Board open. Do not make decorative navigation consume the file-list row budget.

## Ranked recommendations

R1 [must] Layout hierarchy: (1) compact title/menu chrome and current path/breadcrumb for active pane; (2) thin drive and common-folder strips; (3) bookmarks plus action/key-hint strip; (4) dominant file work area; (5) one persistent status/message line. This follows TUI `src/ui/mod.rs:31-64,113-169` and visible elements INV-RENDER-001/002/005/009. Breadcrumbs are additive navigation; drive/common-folder/bookmark/action functions remain keyboard-reachable with original bindings (INV-PLAT-002/003, INV-CONFIG-004).

R2 [must] File work area: default presentation should represent the TUI's actual persisted/default state; the TUI supports a single active pane or `+` split, with two independent pane state and Tab switching (INV-STATE-001/009; INV-CONFIG-002/003). In split, both panes get independent path/title, filter indicator, sort/layout state and selection marker; active cursor highlight must be distinct from multi-selection. Use roughly equal widths, with a 24-character minimum list width where feasible. If one pane renders text preview, allocate it more width as current TUI does (66/34; `src/ui/mod.rs:151-164`) but retain the other pane. In narrow windows collapse inactive pane into a switchable pane, never discard its state; preserve both keyboard contexts and display which pane is active.

R3 [must] Each pane's view modes remain per-pane and cycle as the TUI defines (INV-PE-001; INV-RENDER-003): off/list, details, column preview, grid as characterized in source/state. Details mode keeps name, size, relative modified columns; list names use monospace and ellipsize without hiding cursor/selection; preview must preserve TUI-supported text/image/video/PDF status and error placeholders. Sort headers may invoke the same per-pane cycle only; do not introduce independent comparator semantics.

R4 [must] Keep operational state visible: bottom strip shows transient status/error feedback, current filter/query, sort/layout and selected count/aggregate where applicable; active transfer progress and pause/cancel remain reachable in Copy Board; listing/loading and partial status remain visible. TUI status, selection, count/size, and progress are parity content, not optional decoration (INV-RENDER-005/009, INV-files-ops-012, INV-filesystem-004/005). Modals layer over the work area, trap focus and include the same confirmation text, overwrite policy, and close semantics.

R5 [should] Add a density control / “TUI layout” profile only if needed to preserve the existing terminal geometry and state visibility; it must not alter action/key semantics or persisted TUI state. Window is resizable with sane minimum; remember geometry only in separate desktop preference state unless TUI has a compatible field. No changes to `~/.config/ira/state` bytes without a decision and migration test.

## UX floor implementation and tests

- Mouse: click activates/selects row; double-click opens folder/file equivalent to Enter/`;`; wheel scrolls while keeping cursor/scroll invariant; modified click maps to the exact Space/selection semantics, including cursor movement; context menu offers only the same action IDs as keyboard. Test action convergence and multi-selection against core traces. Mouse behavior is currently intentionally ignored by TUI event loop (INV-INPUT-001), so it is additive.
- Window: native chrome, resize/minimum, maximize restore. Persist desktop geometry separately. Multi-instance handling is unresolved by TUI (INV-STATE-001; ordinary process startup supports separate instance); keep independent app windows/state unless lifecycle audit proves otherwise. Test on macOS/Windows runners.
- Theme/rendering: tokens, system light/dark, contrast-safe focus/selection, HiDPI and font fallback; map existing theme config before adding desktop defaults (INV-CONFIG-005/006, INV-RENDER-004). Screenshot/visual artifacts required on both OSes; source-only review is insufficient.
- Text input: native IME, clipboard, selection, undo in rename/path/create/search/editor inputs, while retaining TUI acceptance/filter rules, cursor editing and paste cleaning (INV-INPUT-005..008/012). Test Unicode and paste on real OS UI; GPUI headless simulated keys supplement but cannot prove IME.
- OS integration: open/reveal and path dialogs invoke corresponding TUI intents (`-`, `[`, `]`, open action; INV-PE-010/013/014); trash must preserve TUI's permanent-delete semantics unless a separately named explicit desktop action is added (INV-files-ops-011). DnD is copy-only by default until explicit OS behavior tests. Platform-specific filesystem semantics remain unverified in Linux-only captures.
- Accessibility: visible focus distinct from cursor and selection; labeled icon-only actions; keyboard traversal in dialogs; contrast and accessible names. Assert focus path and labels structurally, then inspect accessibility tree on native runners.
- Async/feedback: no blocking filesystem/process work in render/action callbacks; list/transfer/size jobs show loading/progress/errors and cancellation where the TUI provides it (INV-filesystem-004/006, INV-files-ops-012, INV-INPUT-011). Test cancel/hide distinction and stale listing generations.
- Empty/error/offline states: reproduce TUI empty/no-match and silent listing-error behavior exactly for parity surface; any richer explanatory detail must not conceal TUI result or consume next key (INV-INPUT-008, INV-filesystem-006). Show volume removed/permission-specific info only after platform behavior is characterized.

GPUI 0.2.2 facts: `uniform_list` is available for lazily building visible rows and examples exist; `TestAppContext`, `VisualTestContext`, simulated keystrokes and `#[gpui::test]` are available in local locked source. Current starter has no components, test support, tests or theme system (`desktop/src/main.rs`; `migration/reports/shell-audit.md`). Exact APIs must be revalidated if lock changes. Context7 unavailable in this review.

Unverified: all macOS/Windows window geometry, HiDPI, IME, clipboard, native dialogs, open/reveal, and accessibility behavior. Linux oracle captures do not validate those platform adapters.
