# Advisory: F-002 redesign spec follow-up by architecture-advisor round 2

Scope reviewed: only S12-S14 and sequencing/compatibility with S1-S11 in `migration/specs/F-002.md`; D-0013; `architecture-redesign-1.md`; pinned `portable-pty 0.9.0` and frozen TUI Crossterm 0.29.0 sources. No implementation or tests changed.

## Verdict: PROCEED WITH CHANGES

### Recommendations

- **R1 [must] S12: ADAPT the teardown contract to distinguish child, writer/slave, reader, and master lifetimes.** `portable_pty::Child` exposes nonblocking `try_wait`, blocking `wait`, `kill`, and a clonable killer; it has no timed wait. `MasterPty` exposes a cloned blocking `Read + Send` handle, with no cancellation/close method beyond dropping it (`~/.cargo/registry/src/.../portable-pty-0.9.0/src/lib.rs:88-102,130-152`). Therefore “bounded shutdown” is an application-level loop/deadline, not a crate guarantee. Specify that child polling/termination/reap has a deadline, writer/slave handles are dropped to signal EOF, the reader consumes available output until EOF under its own deadline, and a blocked reader is unblocked by dropping/cancelling its owned reader handle before a final bounded join. Do not require “close all PTY handles, then drain”: that order can discard buffered output and cannot make a blocking reader drain. If the reader cannot be stopped/joined by the deadline, return a cleanup failure and do not claim successful fixture removal while the thread may still use it. Keep fixture removal last, after child reap and reader termination. Test each ordering with the actual extracted session on all OSes; ensure timeout assertions use generous per-platform bounds, not exact timings. Risk of leaving current wording: it promises behavior the pinned API does not itself provide and may lead to detached reader threads or hangs.

- **R2 [must] S13: ADAPT the bundle to define a deterministic on-disk encoding for byte observations.** The logical distinction and required metadata are coherent with S6/S10. However TOML strings cannot losslessly represent arbitrary filesystem/persisted bytes. Specify a tagged representation (for example UTF-8 text when valid, otherwise base64/hex bytes), path identity, stable observation ordering, and atomic staging writes; terminal screen text should state its decoding/normalization policy separately from raw bytes. Tests should round-trip arbitrary bytes including NUL and invalid UTF-8, and verify that the captured value came from `observe(kind)`, not the trace assertion. Risk: a “typed” bundle could still corrupt the exact-byte evidence S5 requires.

- **R3 [must] S14: ADAPT the payload domain; bracketed-paste framing cannot carry every requested marker-like payload unambiguously.** Frozen Crossterm 0.29.0's Unix parser recognizes `ESC[200~ ... ESC[201~`, ends at the first closing marker, and constructs the payload via `String::from_utf8_lossy` (`crossterm-0.29.0/src/event/sys/unix/parse.rs:812-821)); it has no escaping layer. Thus a payload containing literal `ESC[201~` is truncated/misframed, and invalid UTF-8 cannot round-trip (though the schema’s String payload excludes invalid UTF-8 already). Require explicit rejection of payloads containing the closing marker, unless a separate proven transport mechanism is added. “Marker-like” tests should distinguish harmless partial/opening-like sequences—which should remain payload—from the exact terminator, which must be rejected. Retain newline and escape-like payload coverage. Crossterm’s Windows event source has no corresponding `Event::Paste` parser in `src/event/sys/windows`; on Windows the frozen TUI may not produce paste events through its native event backend. Define the Windows scenario result from a live probe: either demonstrate the actual paste event path on ConPTY, or report paste as unsupported by the frozen Windows oracle and fail/limit that scenario explicitly rather than asserting Unix parser semantics cross-platform. Risk: S14 currently requires a behavior that the selected terminal protocol and Windows event backend may not provide.

- **R4 [should] Sequence: ADAPT to make lifecycle tests precede behavior work, but merge the seam and contract before serial golden/paste changes.** S12 first is sound and matches S1/S3 target lifecycle and S8 cleanup. Keep the helper child behind the same extracted PTY session constructor and use direct process/reader/fixture evidence; scripted target tests remain orchestration-only. Then land S13 bundle format and its round-trip tests before S14 transport work, so paste behavior can be captured as an observation. Run the same frozen-tag live test in the native platform matrix and record platform-specific unsupported behavior explicitly. This ordering minimizes shared-file churn while preserving D-0013’s serial write sets. Risk of combining the three changes: gaps can be masked by a shared abstraction change.

Risks not covered by any recommendation: none beyond F-150’s already stated native OS and license-evidence gate.
