# F-002 architecture redesign review

Scope reviewed: F-002 spec; `tools/ira-parity/src/{runner,trace,golden}.rs` at `5ae8bf38346e7ff20f636f9928eebcf29bc97ab6`; contract tests and reports `dev-1.md`–`dev-3.md`, `logic-review-1.md`, and `adversarial-review-1.md` in the fix worktree. The adversarial report covers remediation through `62db2ce`; dev-3 records the subsequent `5ae8bf3` fix for ADV-50.

## Verdict: RETHINK

Do not discard the verified schema, resolver, normalization, environment isolation, or comparison fixes. Do restart the remaining F-002 work with a new developer and a sharpened architecture. Three cycles exposed a structural testing seam: `TraceTarget` orchestration and the actual PTY process lifecycle are separate execution paths, so scripted lifecycle tests cannot prove cleanup of the OS child, PTY, and reader. Golden capture is also modeled as trace serialization rather than an observation capture. Another narrow patch that turns scripted GAP tests green would not satisfy S6–S8/S10.

## Recommendations (ranked)

R1 [must] Restart the remaining work with a new developer; preserve commits through `5ae8bf3` as the base. First split lifecycle ownership from scenario orchestration: an owned PTY session should hold child, master/slave handles, reader, and fixture; one bounded shutdown path should kill/reap, close PTY handles, join/drain the reader, then remove the fixture, retaining primary and cleanup errors. Keep `TraceTarget` for logical/fake-target contract tests, but do not use it as lifecycle evidence. `runner.rs:465–563` currently creates the PTY and owns its reader inline; `PtyChildLifecycle::shutdown` at `runner.rs:897–950` polls and detaches a reader on deadline; `run_oracle_with_baseline` has early `?` exits after child startup (`runner.rs:485–550`). GAP tests 29/30 call `ScriptedTarget` (`tests/f002_contract.rs:718–760`), while the reviewer explicitly found they only test doubles. Risk of ignoring: cleanup claims remain indirect, and early errors can lose diagnostics or strand handles.

R2 [must] Add a small real helper-child executable/test fixture and exercise the same extracted PTY session used by the TUI adapter: (a) normal success, (b) timeout while child is alive, (c) child exits while the reader is active, (d) reader/PTY failure, and (e) fixture removal after handles close. Assert process exit/reap, reader join, cleanup ordering, bounded duration, and combined errors. Run these on Linux, macOS, and Windows MSVC; Windows must prove ConPTY handles are closed before directory removal. Replace the misleading scripted lifecycle GAP bodies with these concrete tests, retaining separate unit tests for orchestration. `tests/f002_contract.rs:664–760`; `runner.rs:897–950`; spec S7–S8 and verification obligation 3. Risk: platform-specific handle leaks and timeout hangs can survive Linux-only or mock-only green tests.

R3 [must] Make capture produce a typed observation bundle, not `initial_screen.toml` containing the input trace. For each declared observation, write captured value plus kind/scenario identity; for terminal output include the actual observed screen and dimensions, for file observations preserve bytes, and record the ordered logical events and capture metadata. Keep staging-only writes and pending logic-review status. `golden.rs:86–111` currently writes `t.to_toml()` to `initial_screen.toml`; metadata `events` is `Debug` text (`golden.rs:18–25`) and contains no captured-output manifest. This gap is acknowledged in `dev-2.md` and is required by S6/S10. Update spec terminology if needed to define bundle paths/schema, but do not weaken the requirement that candidates contain oracle observations. Risk: reviewers cannot inspect the claimed oracle output or compare an approved golden to replay results.

R4 [must] Preserve paste as a paste event at the PTY boundary. Encode `InputEvent::Paste` using the bracketed-paste framing expected by Crossterm, and test the actual frozen TUI's `Event::Paste`/`handle_paste` behavior with payloads containing newlines, escape-like bytes, and marker-like text; plain `value.as_bytes()` is indistinguishable from ordinary typing (`runner.rs:1044–1045`). The oracle enables bracketed paste in `src/tui.rs:61–67`, and dispatches `Event::Paste` separately to `app.handle_paste` in `src/main.rs:63–68`. Keep `Text` a distinct ordinary-input path. If the PTY protocol cannot represent a payload unambiguously, define an explicit unsupported case rather than silently converting paste to typing. Risk: tests validate a different editing/paste behavior than users receive.

R5 [should] Keep the latest qualified-ref, expected-observation, readiness, platform, and normalization fixes unchanged unless a new failing probe requires modification. Their focused red/green evidence is recorded in `dev-2.md` and `dev-3.md`; adversarial review verified ADV-44/45/46/49 and reported ADV-50, then dev-3 used `refs/tags/<tag>^{commit}` at `5ae8bf3`. Re-run logic and adversarial suites on the redesigned lifecycle/capture code, not merely the focused tests. Risk of ignoring: the redesign could regress correctness already demonstrated.

R6 [should] Treat native macOS and Windows execution as a dedicated F-150 integration barrier after the session/capture interfaces stabilize. F-002 spec already assigns CI integration, dependency-license closure, and live three-OS replay to F-150; Linux evidence cannot close this obligation. Have F-150 run all committed live scenarios on macOS 14 and Windows MSVC/ConPTY, include the real lifecycle tests above, audit the resolved `portable-pty` license closure, and retain CI run links/artifacts. Do not wait for native proof to redesign the Linux-testable ownership model, and do not mark F-002 verified until the F-150 evidence exists. Risk: cross-platform behavior remains asserted from code inspection only.
