# Spec F-150: Cross-platform migration CI and dependency-license closure

Matrix row: F-150 | Inventory: platform build/replay and dependency-compliance obligations | Wave: 0 | Deps: F-001, F-002
Status: approved for red-test preparation after architecture/platform pre-review; workflow implementation awaits committed red tests.

## Outcome

Provide repeatable CI evidence that the TUI oracle and GPUI desktop shell build from locked dependencies on Linux, macOS, and Windows; live F-002 oracle scenarios execute through native PTY/ConPTY on each OS; and the standalone parity harness's complete resolved dependency closure has an audited license policy. Do not create releases or distribute CI binaries as release assets.

## Requirements

1. Pull requests, pushes to the integration branch, and manual dispatch run the migration workflow. Use explicit labels `ubuntu-24.04`, `macos-15` (arm64), and `windows-2022` (MSVC/ConPTY). Record `ImageOS` and `ImageVersion` on every job. Do not change F-001 packaging support: the separate desktop-build workflow remains unchanged.
2. Pin one exact stable Rust toolchain version across all jobs (the current manager environment is Rust 1.98.1; verify it on all three runners before finalizing the pin) and report `rustc -Vv` and `cargo -V`. Root TUI, `desktop/`, and `tools/ira-parity/` are separate locked Cargo packages. For each manifest run explicit `cargo build --manifest-path <manifest> --locked`, `cargo test --manifest-path <manifest> --all-targets --locked`, `cargo clippy --manifest-path <manifest> --all-targets --locked -- -D warnings`, and package-scoped format checking. Do not use workspace commands that silently omit one package.
3. Every OS runs the exact live F-002 scenario test `f002_contract::tagged_oracle_trace_replays_on_linux_macos_windows` against the verified frozen `tui-oracle-baseline` tag using native PTY/ConPTY. Select that unignored test explicitly; do not run blanket `--ignored` because it mixes unrelated open GAP probes. Require and report exactly one selected test passed, scenario ID, baseline SHA, and cleanup outcome. CI checkout/fetch setup must make the immutable baseline tag available and print the verified SHA. Other Linux-only schema/contract probes are additional coverage, not substitutes for macOS and Windows native replay.
4. Caches are keyed by OS, target, exact toolchain, and all relevant lockfiles; cache hits must not conceal command execution. Every test/build/lint job executes in a clean checkout and records exact commands, versions, runner image, and commit SHA.
5. Audit the full dependency closure resolved by `tools/ira-parity/Cargo.lock`, including target-specific Windows crates. Pin the cargo-deny version; commit its policy and a reproducible package/version/SPDX/source inventory; fail on unknown, unreviewed, or disallowed licenses. Demonstrate that the check includes every target edge (or explicitly check Linux, macOS, and Windows target profiles). Do not audit only root or desktop lockfiles.
6. Prototype native desktop smoke on macOS and Windows hosted runners before finalizing the workflow: start the production GPUI binary, assert an OS-native window exists/is visible, request a close, and require clean process shutdown within a deadline. A process-start/exit check or successful linking is insufficient. Record runner image and outcome. If either hosted runner cannot support a reliable window assertion, keep this requirement unresolved and propose a controlled interactive self-hosted GUI runner; never relabel compilation as a window smoke test.
7. CI is evidence only for the exact commit checked. The workflow does not publish GitHub releases, upload binaries as release assets, or change desktop packaging/signing behavior. Retention-limited diagnostic logs or test reports are acceptable when needed to inspect failures.

## Error handling and determinism

- Use `cargo ... --locked`; a lockfile drift fails.
- Propagate all test/build/license/smoke exit statuses. No `continue-on-error`, hidden platform skips, or blanket `|| true`.
- Use a bounded test timeout and make PTY children/readers/worktrees/fixtures finish cleanup before the job succeeds.
- Retain OS/toolchain/target/dependency-license evidence in the job summary or artifacts for the configured finite retention period.

## Write-set

Integrator-owned: `.github/workflows/migration-ci.yml`, a narrowly scoped license policy/config and generated dependency-license inventory under `tools/ira-parity/`, CI instructions under `migration/` (not manager-owned STATE, matrix, decisions, or journal), and workflow-only smoke helpers if pre-review approves them. Do not edit root or desktop manifests/lockfiles, F-002 source/spec/tests, desktop packaging workflow, or TUI source/tag. Manager owns matrix/state/journal changes.

## Test-first plan

- F-002 must first be integrated; `tools/ira-parity/` currently lives only on its feature branch. Before implementation, adversarial reviewer adds a workflow/CI contract check in `tests/ci/` or a script-level test proving required OS matrix entries, three explicit locked package commands, named live trace invocation, no release publishing, and explicit license policy enforcement; demonstrate it fails against the current absence of `migration-ci.yml`.
- Validate workflow syntax and expressions, license inventory generation and unknown-license failure, and test invocation locally where possible.
- Require successful CI runs on Ubuntu, macOS, and Windows. Save run URL, commit SHA, OS and job results in the F-150 report.
- A macOS/Windows build result alone does not satisfy live PTY/ConPTY or native window smoke clauses.

## Verification boundary

F-150 does not verify feature parity beyond the committed F-002 traces, does not make a macOS/Windows native window claim without an actual smoke assertion, and does not waive any open F-002 GAP. F-002 remains unverified until live traces pass on all three native runners and the license audit is complete.
