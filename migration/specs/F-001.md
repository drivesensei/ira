# Spec F-001: Core crate and TUI/GPUI boundary

Matrix row: F-001 | Inventory: INV-DOCS-002, INV-DOCS-003 | Wave: 0 | Deps: none
Status: draft for architecture, platform, and UX pre-review

## Oracle behavior

This is a structural foundation row and introduces no new end-user behavior. The frozen TUI remains the oracle and retains its existing package, binary, CLI, and behavior.

1. [S1] The root package `ira` remains independently buildable as the existing Ratatui TUI using its root manifest and lockfile. (`Cargo.toml`; `migration/inventory/tests-docs-orphans.md`, INV-DOCS-001/002)
2. [S2] The desktop remains an independently buildable native GPUI application using the existing separate manifest and lockfile, with its existing window/button interaction. (`desktop/Cargo.toml`, `desktop/Cargo.lock`, `desktop/src/main.rs`; `migration/reports/shell-audit.md`)
3. [S3] A new `ira-core` package owns the shared UI-neutral boundary. Its library has no dependency on GPUI, Ratatui, or Crossterm, and its Rust source does not import those crate names. Neither UI host is allowed to import the other host's types. F-001 creates only the package boundary and does not move feature behavior from the TUI.
4. [S4] Both app manifests depend on `ira-core` by a local path. Cargo lockfiles remain separate: root builds resolve/update only root `Cargo.lock`, and desktop builds resolve/update only `desktop/Cargo.lock`. Do not create a Cargo workspace spanning the independently pinned GPUI package.
5. [S5] The existing root test suite and desktop build continue to pass after this structural boundary is introduced. Both targets remain launchable; no TUI screen, output, key, persisted file, or side effect changes.
6. [S6] F-001 leaves lifecycle, actions, keymaps, state, paths, persistence, filesystem, platform services, dialogs, theming, and file-list behavior to their owning rows. The starter view may only receive the minimum module/wiring refactor needed to express the GPUI adapter boundary.

## Triggers and surface

No new user-visible `kind:name` surfaces. This row covers package/dependency architecture and build contracts only.

## State and effects

No application state or filesystem effects are added. `ira-core` starts as a minimal library crate with an explicit public module boundary and no behavior claim. Feature modules and their contracts are introduced by their corresponding later rows.

## Errors and edge cases

- Missing or invalid path dependency must fail the boundary check/build.
- Adding a host UI dependency to `ira-core` must fail the boundary check.
- Breaking either independent lockfile/build path must fail acceptance.

## Config influence and persistence

None. Keep root and desktop lockfiles independent and committed. Do not alter user-facing persisted formats.

## Platform notes

The current package boundary is OS-neutral. GPUI signatures used by the existing shell were checked against the exact local `gpui 0.2.2` source in `~/.cargo/registry/src/index.crates.io-*/gpui-0.2.2`: `Application::on_reopen` (`src/app.rs:198-208`), `App::open_window` (`src/app.rs:943-976`), and `App::activate` (`src/app.rs:979`). Context7 is unavailable in this environment; the pinned source and existing compiling shell are the authoritative API evidence.

## GPUI/desktop surface (parity floor only)

Preserve the current native window startup/reopen path and button click behavior. This row does not claim the full native lifecycle parity in F-115, nor the broader UX-floor behavior in F-114..F-123.

## Write-set and dependencies

Allowed write-set: root `Cargo.toml`, root `Cargo.lock`, `desktop/Cargo.toml`, `desktop/Cargo.lock`, `crates/core/**`, narrowly scoped `desktop/src/main.rs` boundary wiring, and `tests/boundary/**`.

Explicit non-goals: no edits under root `src/**` or `tests/*.rs`; no TUI behavior change; no feature extraction; no GPUI upgrade; no unified Cargo workspace; no app lifecycle redesign; no app icon/packaging work.

## Test plan

- S1: boundary check confirms root manifest still identifies package/bin `ira`, has its terminal UI dependencies, and can build with root lockfile.
- S2: boundary check confirms desktop remains `ira-desktop`, GPUI remains pinned at 0.2.2, and the desktop manifest builds with its own lockfile.
- S3: boundary check rejects `gpui`, `ratatui`, or `crossterm` in `ira-core` direct dependencies and source imports; core library compiles for the host target.
- S4: check Cargo metadata/package graph for path dependencies and independent lockfiles; build commands are `cargo build --locked` and `cargo build --manifest-path desktop/Cargo.toml --locked`.
- S5: existing root tests run with `TMPDIR="$PWD/target/tmp" cargo test --locked`; both build commands above pass; native window launch smoke remains manual/OS CI evidence.
- S6: scope review confirms no feature modules or behavior beyond this boundary are introduced.

The adversarial reviewer must first add executable red boundary checks under `tests/boundary/` and record GAP notes before implementation. Test names and precise commands are filled into this spec when the red test artifact is returned.

## Open questions

None. Architecture pre-review confirmed the shared local path dependency from both app manifests, with independent lockfiles and no umbrella workspace.
