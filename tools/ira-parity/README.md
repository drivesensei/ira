# IRA parity harness

This standalone crate restores the preserved F002 trace parser, scripted observation runner, typed golden bundles, environment isolation and PTY adapter. It does not establish full desktop parity. Run selected tests from this directory so historical relative oracle fixture paths resolve.

The current single-worktree policy supersedes implicit baseline acquisition and cleanup: the resolver reads a locally present, commit-pinned tag, exports only bounded regular Git blobs beneath the explicit canonical `CARGO_TARGET_DIR`, and retains that export. It never fetches, registers/removes worktrees, changes refs, or automatically deletes exported source. `source_export_is_verified` checks retained content; historical `worktree_is_detached_and_clean` returns false because an export is not a Git worktree.

`resolve_and_build` reuses only a cache bound to commit, platform, target, toolchain, lockfile, profile and executable hash. A cache miss requires explicit `OracleBuildPolicy`; default calls cannot start a compiler. Opt-in builds are offline, locked and bounded to at most 180 seconds/1 MiB per captured stream. Windows opt-in builds are refused pending process-tree containment; verified caches remain usable. The caller must separately authorize and monitor aggregate target growth. No oracle builds are part of the initial scripted-test validation.

Preserved fetch/worktree/cleanup contracts describe historical behavior and are not current acceptance claims. The old active missing-tag-fetch probe is explicitly ignored with that policy rationale; local refusal/ref-preservation has dedicated replacement tests. The existing canonical red contract is retained unchanged, including its ignored historical gaps. Avoid broad `cargo test`: live capture and lifecycle suites require their own fixture/process/source review. Keep synthetic HOME, macOS fixed home, XDG paths, TEMP/TMPDIR and cache routes beneath the canonical target; preserve normal toolchain locations explicitly. The running user-facing desktop candidate is a separate verified CI build and is untouched by harness tests.

Process limits do not by themselves prove whole-descendant/reader retirement on every platform. Windows oracle builds remain refused; Git metadata helpers return a bounded direct-child error if reaping cannot be observed. Unix export verification uses no-follow directory FDs and stable file metadata/hash, but is not a claim of fully race-proof root ancestry. The caller must keep isolated fixture ownership and an external cumulative-output budget monitor.
